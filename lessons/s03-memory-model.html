Part 1

The stack and the heap

A running Java program keeps its memory in two places. The stack holds one frame per method that's currently running: a small scratch space for that method's local variables. A new frame goes on top when a method is called, and comes off when it returns. The heap is where every object lives: arrays, Strings, anything made with new. Variables on the stack point into the heap with arrows.

Step 1 / 12

The rule. Java always hands a method a copy of what's in the variable. For an int that's a copy of the number. For an array or any object, it's a copy of the arrow.

So a method that follows the arrow and changes the object (arr[0] = 9) changes the caller's object. A method that points its arrow somewhere new (arr = new int[3]) only changes its own copy.

This is exactly how JavaScript behaves too. If you've ever had a React bug where you pushed into an array from state and the screen didn't update, it's the same picture: one array, two arrows.

Errors you'll probably meet today

expected: not same but was: <[I@1ed1993a>

Your copy or append handed back the same array it was given. return arr; returns a copy of the arrow, not a copy of the array. Make a new one with new int[...] and fill it.

[I@1ed1993a is how Java prints an array: [I means "array of int", and the part after @ is an id for that object. Two arrows to the same array print the same id.

array contents differ at index [1][0], expected: <0> but was: <1>

From gridRowsAreIndependent. The test set g[0][0] = 1 and the 1 showed up in row 1 as well, so your rows are one shared array. That's Way A in Part 3. Each row needs its own new.

java.lang.ArrayIndexOutOfBoundsException: Index 2 out of bounds for length 2

A runtime crash, not a compile error. In append it usually means you wrote the new value into the old array: arr[arr.length] = x. The old array has no room for it. Write it into the new, longer one. In a loop, check you used < and not <=.

error: incompatible types: unexpected return value

You wrote return arr; inside a void method like fill. A void method returns nothing. It doesn't need to: the caller already has an arrow to the array you changed.

error: missing return statement

copy, append and grid promise to return an array, and some path through your method doesn't. Add return result; at the end.

System.out.println(nums) prints [I@6d06d69c

Printing an array prints its id, not its contents. For debugging, use System.out.println(Arrays.toString(nums)); with import java.util.Arrays; at the top. For a 2D array, Arrays.deepToString(grid).
