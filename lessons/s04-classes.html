Part 1

A class is a blueprint

You've written JS classes in React code. A Java class is the same idea: a blueprint that says what boxes (fields) every object gets, and what it can do (methods). new stamps out an object from the blueprint and runs the constructor to set it up.

JavaScript
Java

Three differences. Java fields are declared up front, with types. The constructor is named after the class and has no return type. And inside a method you can drop this.: plain score means this object's score.

The rule. A plain field is one box per object: every new makes a fresh set. A static field is one box for the whole class, shared by every object, and it exists before any object does.

Same for methods. A plain method runs on an object (a.addPoints(10)) and can use its fields. A static method runs on the class (Player.something()) with no object at all. That's why TwoSum.twoSum(nums, 9) never needed a new.

Part 5

Make the tests green

Your files are in src/main/java/phase0/s04_classes/. This time you write the fields yourself. Two new words you'll need:

private on a field means only code inside the class can touch it, like #count in a JS class. The tests can't write c.count = 99; they have to go through increment() and value(). The class decides what's allowed.

final on a field means it's set once, in the constructor, and never again. Point's fields are public final: anyone can read p.x, nobody can change it.

Errors you'll probably meet today

expected: <likes> but was: <null>

Your constructor says label = label;. That copies the parameter into itself and leaves the field at its default, null. Write this.label = label;. Part 4 shows it happening.

twoCountersAreIndependent expected: <2> but was: <12>

Your count field is static, so every Counter shares one box. Every other test is quietly adding to it too, which is why you see odd numbers like 11 or 12 that change when you run a single test. Remove static from the count.

anOldTicketKeepsItsId expected: <1> but was: <3>

That's the trap card from Part 3. id() is returning the shared counter, which keeps moving as new tickets are made. In the constructor, copy the counter's value into a per-ticket field, and have id() return that field.

error: non-static variable count cannot be referenced from a static context

A static method (issued() or resetCount()) is trying to read a per-object field. A static method runs with no object, so there's no "this ticket's" field to read. Either the field should be static too, or the method shouldn't be static.

error: cannot find symbol   symbol: variable count

You're using a field you haven't declared yet. Fields go inside the class but outside any method, usually at the top: private int count;.

error: cannot assign a value to final variable x

Probably in moved: you tried this.x = x + dx;. A final field can't change after the constructor. Don't move this point; make a new one: return new Point(...);.

error: variable x might not have been initialized

Every constructor has to set every final field. Usually it's Point(): you left it empty, so x and y were never set. Set them to 0, or call the other constructor.

error: call to this must be first statement in constructor

Inside Point(), this(0, 0); has to be the very first line. Nothing can come before it.

expected: <(3, 4)> but was: <phase0.s04_classes.Point@1b6d3586>

Same thing you saw with arrays in s03: with no toString of your own, Java prints the class name and an id. Your toString must return a String built from x and y, with the brackets, comma and space.
