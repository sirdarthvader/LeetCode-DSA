The rule. An ArrayList is a row of numbered boxes: jump to box i instantly, but to find a value it looks at the boxes one by one. A HashMap files each value under a key and goes straight to it. A HashSet is a HashMap with keys and no values: it answers "is this in here?" in one look, and it never holds the same thing twice.

Part 5

Loops, and the order surprise

The for-each loop from s01 works on all three. The colon reads as "in": for each n in nums.

Order. An ArrayList keeps the order you gave it. A HashMap or HashSet keeps no order you can count on, unlike a JS Map or Set. You saw it in the playground: put ada, lin, eve, and it prints {lin=29, eve=23, ada=36}. When order matters, loop over something that has one.

Hands off while looping. Don't add to or remove from a collection while a for-each loop is walking it. Java stops with a ConcurrentModificationException.

Decoder

Errors you'll probably meet today

error: unexpected type   required: reference   found: int

You wrote List<int>. Collections hold objects only. Write List<Integer>; Java wraps each int into an Integer for you.

error: cannot find symbol   symbol: class ArrayList

Missing import. Add import java.util.ArrayList; under the package line. Same for HashMap and HashSet.

error: cannot find symbol   symbol: variable length   location: variable words of type List<String>

Lists use words.size(). Arrays use nums.length, with no brackets, and Strings use s.length(), with brackets. Three spellings for one idea: the compiler always tells you which one you mixed up.

java.lang.IndexOutOfBoundsException: Index 3 out of bounds for length 3

You asked for a box that isn't there. In removeAll it's usually list.remove(value): with an int, remove means "remove the box at this index", not "remove this value". In JS a missing index gives undefined. Java stops the program instead.

removeAllRemovesTheValueNotTheIndex expected: <[10, 20, 30]> but was: <[10]>

The same trap without a crash: remove(1) removed the box at index 1, three times. To remove by value, either loop over indices and call remove(i) where the value matches, or make the value an object: list.remove(Integer.valueOf(value)).

removeAllRemovesNeighbours expected: <[1]> but was: <[5, 1, 5]>

You loop forwards and remove as you go. When you remove box i, everything after it shifts one place left, so the next value moves into box i. Then i++ skips right past it. Loop backwards from the end, or only move on when you didn't remove anything.

java.util.ConcurrentModificationException

You removed from the list inside a for-each loop over that same list. Java won't let a collection change while a for-each is walking it. Use an index loop instead.

NullPointerException: Cannot invoke "java.lang.Integer.intValue()" because the return value of "java.util.Map.get(Object)" is null

Probably counts.get(w) + 1 on a word you haven't seen yet. get returned null, and null + 1 has no answer, so Java crashes. Look up getOrDefault in the Part 1 table.

mostCommonTieGoesToTheWordThatAppearsFirst expected: <b> but was: <a>

Or <amy> but was: <zoe>. You're looping over the map to find the winner, and the map's order isn't the order the words came in (Part 5). Loop over the words array instead and look each word's count up in the map.

bigInputIsFast: execution timed out after 2000 ms

Your answer is right but too slow for 200,000 numbers. LeetCode calls this Time Limit Exceeded. Somewhere you're looking at every number for every number. Go back to the yellow badge in the playground and compare the three collections.
